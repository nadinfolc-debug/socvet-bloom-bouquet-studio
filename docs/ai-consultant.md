# ИИ-консультант Соцвета

Чат подбирает букеты, отвечает о доставке и уходе. Товары берутся из нового
каталога Supabase. Консультант не читает заявки, не отправляет обращения,
не меняет корзину, не принимает оплату и не оформляет заказ. Для флориста
есть ссылка на существующую форму индивидуального заказа на главной.

## Активация

1. Завершить переход на собственный каталог по `docs/native-catalog.md`:
   применить миграцию 0005, перенести товары, цены, описания и фото.
2. В секретах СЕРВЕРНОГО окружения хостинга добавить `OPENAI_API_KEY`.
   Не использовать префикс `VITE_` для ключа, не коммитить его в `.env`
   и не пересылать в переписке. Использовать отдельный проект/ключ OpenAI.
3. Задать серверные переменные `CONSULTANT_ENABLED=true` и, при необходимости,
   `OPENAI_MODEL=gpt-4.1-mini`. Выбранная модель должна поддерживать
   `/v1/chat/completions` и Structured Outputs (`json_schema`).
4. Для браузерной сборки задать `VITE_CONSULTANT_ENABLED=true`.
   Без этого виджет скрыт. Это публичный флаг, он не заменяет серверный.
5. Серверу нужны `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` (те же, что для заявок)
   и исходящий HTTPS к `api.openai.com`. Service role не используется.
6. Проверить и утвердить фактические условия доставки в `src/lib/shop-info.ts`.
   Они общие для страницы доставки и консультанта. Контакты в исходном макете
   обозначены как вымышленные, поэтому ИИ направляет в форму на сайте.
7. Настроить общий лимит запросов на шлюзе/хостинге для серверной функции
   `askConsultant`, лимиты проекта OpenAI и мониторинг расходов. Защита в коде:
   30 запросов в минуту и 3 одновременно на один экземпляр сервера. При нескольких
   экземплярах или холодных стартах она не обеспечивает общий лимит.
8. Выполнить `npm test`, `npx tsc --noEmit`, `npm run build`, опубликовать сборку
   и проверить реальный ответ ИИ, уточняющий вопрос и переход в карточку.

Оба флага позволяют отдельно отключать чат/сервер. После изменения публичного
флага требуется пересборка. Ключ и другие серверные переменные должны быть
доступны в runtime опубликованного приложения, а не только во время сборки.
Само редактирование кода не создаёт ключ и не активирует платёжный аккаунт OpenAI.

## Поведение и ограничения

- Чат сообщает, что посетитель общается с ИИ, и требует согласия на отправку
  сообщений OpenAI. Телефон, адрес и платёжные сведения запрашиваются только
  в обычной форме заказа/обращения, не в чате. Предупреждение не является
  автоматическим удалением случайно введённых персональных данных.
- Текущий диалог живёт в памяти страницы; в localStorage и базе не сохраняется.
  Закрытие окна не очищает историю; кнопка очистки и перезагрузка удаляют её.
  Условия хранения на стороне OpenAI определяются условиями провайдера.
- На каждый вопрос загружается до 60 недавно изменённых опубликованных букетов;
  недоступные варианты исключаются. Для большого каталога нужна отдельная
  доработка поиска. При ошибке базы чат не придумывает наличие, а сообщает о сбое.
- Клиент передаёт только роли user/assistant и текст; не может передать
  служебную инструкцию, цены, каталог или имя модели. Контекст ограничен
  последними пятью парами сообщений и новым вопросом; до 1200 символов
  на сообщение и до 8000 суммарно. Ответ ограничен 600 выходными токенами.
- Ответ отображается обычным текстом. Карточки, ссылки и цены собираются сервером
  по существующим доступным товарам, а не берутся из сгенерированного ответа.
  Текстовые советы ИИ всё равно могут содержать ошибки; заказ подтверждает флорист.
- При сбое вопрос остаётся в поле ввода. Повторная отправка выполняется посетителем;
  автоматических платных повторов и фоновых запросов при открытии чата нет.
- Виджет скрыт на страницах входа, админки и демонстрации админки.

Проверки с моками провайдера не заменяют реальную проверку после настройки ключа.
